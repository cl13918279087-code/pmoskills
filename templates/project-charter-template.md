## 5. 项目管理规范

### 5.1 计划管理

**计划制定流程：**
```
质量管理组提出主计划框架（含里程碑）→ 各项目组反馈意见 →
质量管理组调整形成项目主计划 → 总体组审核 → PMO/委员会审批发布 →
各项目组制定子计划 → 质量管理组审核子计划 → 发布执行
```

**计划制定要求：**
- 任务覆盖全部工作内容，完成全部任务即完成项目
- 每项任务描述清晰、无歧义
- 计划时间要求到天
- 准确描述任务间关联关系（前置任务）
- 每项任务落实到具体负责人和执行人
- 明确任务交付物（报告、手册、清单、表单、会议纪要等）
- 最小级别任务工期不超过一周；提前两周做滚动细化

**计划跟踪：**
- 常规阶段：周跟踪，进度更新到周报
- 关键开发阶段：日跟踪，每日更新详细开发计划
- 变更偏离>10%：启动计划变更流程

**计划变更：**
```
变更申请人提出 → 质量管理组评估影响 →
总体组审核 → PMO/委员会审批 → 发布新计划 →
各项目组修订子计划
```

### 5.2 问题/风险管理

**升级路径：**
```
项目组（第一责任人）→ 质量管理组（升级受理）→ 总体组（重大问题）→ PMO → 委员会
```

**问题跟踪表字段：** 问题描述 → 发现日期 → 优先级 → 责任人 → 解决时限 → 当前状态 → 升级记录

### 5.3 沟通管理

| 沟通类型 | 频率 | 责任人 | 提交时间 | 提交方式 |
|----------|------|--------|----------|----------|
| 工作周报 | 每周 | 项目经理 | 周五12:00 | SVN + 邮件 |
| 项目月报 | 每月 | 项目经理 | 每月最后工作日24:00 | 邮件 |
| 项目群简报 | 每月 | 质量管理组 | 每月第一个工作日24:00 | 邮件 |
| 项目群周例会 | 每周 | 质量管理组 | 周一 | 会议 |
| 项目组周例会 | 每周 | 项目经理 | 周五 | 会议 |
| 阶段汇报会 | 重要节点 | PMO | 节点完成后 | 会议 |

### 5.4 质量管理

**质量审计类型：**
| 审计类型 | 审计内容 | 执行主体 |
|----------|----------|----------|
| 产品审计 | 各阶段交付物质量（文档规范、范围完整性、功能点） | 质量管理组 |
| 过程审计 | 项目执行是否按规定动作执行（WBS制定、评审记录等） | 质量管理组 |

**质量问题处理：**
- 苗头提醒 → 质量管理组跟踪解决情况
- 重要质量问题 → 报总体组决策
- 重大质量问题 → 报PMO/项目管理委员会

### 5.5 需求管理

**需求变更判断标准（重大变更满足任一）：**
- 工作量超出总工作量10%
- 里程碑点推迟
- 其他影响高层计划安排

**需求变更流程：**
```
变更申请 → 评估是否重大变更 → 重大变更：组织评审（技术可行性、关联影响、风险分析） →
总体组审批 → 实施变更 → 更新需求跟踪矩阵
```

### 5.6 架构管理

| 管理领域 | 流程 | 责任组 |
|----------|------|--------|
| 应用系统基线 | 申请→审核→修改→发布 | 技术架构组 |
| 服务/数据规范 | 建议→形成规范→审核→发布 | 技术架构组 |
| 架构例外 | 申请→技术架构组审核→科技部门审批→执行 | 技术架构组 |
