# project-charter-writer v2.0

## 核心原则（三条铁律）

| 原则 | 说明 |
|------|------|
| **1. 逐项采集** | 信息按字段独立采集，用户确认一项再问下一项，不一次性索要全部信息 |
| **2. 假设标注** | 用户无法提供的信息，用 `[假设值-请核对]` 标注，生成后提醒用户逐项核对 |
| **3. 表格展示** | 所有输出章节均用表格形式，不再使用下划线填写式或纯文本段落 |

## 触发条件

用户说"帮我立项"、"生成项目章程"、"启动项目"或类似意图时触发本技能。

## 操作流程（5步）

```
Step 1: 欢迎与范围确认
Step 2: 逐项信息采集（每项独立确认）
Step 3: 信息汇总确认
Step 4: 生成章程文档
Step 5: 下游Skill建议
```

## 信息采集（Step 0 — 前置条件检查）

> ⚠️ **执行前必读**：项目章程编写需要明确的项目背景和干系人信息。信息缺失时应主动采集，而非直接生成空白文档。本Skill v2.0采用5步流程，每步都有独立确认节点。

### Step 0.1 — 章程数据缺口检查

| 数据项 | 是否已知 | 未提供时的处理 |
|--------|---------|--------------|
| 项目基本信息（名称/类型/周期） | 请告知 | 引导用户Step 1确认基本信息 |
| 项目背景与目标 | 请告知 | 在Step 2中标注 `[假设值-请核对]` |
| 干系人清单 | 请告知 | 在Step 2中标注 `[假设值-请核对]` |
| 治理架构 | 请告知 | 在Step 2中提供标准模板 |

### Step 0.2 — 数据确认


## Step 2 — 逐项信息采集（每项独立确认）

**通用规则**：
- 每轮只问 **1个主题**，不连环追问
- 用户回答后，**复述确认**（"您确认：XXX，对吗？"）
- 用户无法回答 → 标注 `[假设值-请核对]`，记录在采集确认单，继续下一项
- 所有字段采集完才进入 Step 3
