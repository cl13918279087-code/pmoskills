## 2. ETC核心公式

### 2.1 基础EVM指标

| 指标 | 公式 | 说明 |
|------|------|------|
| 成本偏差 CV | CV = EV - AC | 正值表示成本节约，负值表示成本超支 |
| 进度偏差 SV | SV = EV - PV | 正值表示进度超前，负值表示进度落后 |
| 成本绩效指数 CPI | CPI = EV / AC | >1表示成本节约，<1表示成本超支 |
| 进度绩效指数 SPI | SPI = EV / PV | >1表示进度超前，<1表示进度落后 |
| 完工预算 BAC | BAC = baseline_budget | 项目基线总预算 |

### 2.2 ETC重新估算公式

根据银行项目管理要求，提供三种ETC估算方法，由项目管理者根据实际情况选择：

#### 方法一：基于CPI的ETC估算（适用于成本超支）

```
ETC = (BAC - EV) / CPI
```

**适用条件**：进度基本正常（SPI ≥ 0.9），但成本超支

**典型绩效因子调整**：
```
CPI_adjusted = CPI × PF_bank
PF_bank = 0.95 × PF_complexity × PF_resource × PF_scope
```

其中：
- PF_complexity：系统复杂度因子（核心系统1.15，支付系统1.10，外围系统1.05）
- PF_resource：资源可用性因子（总行科技1.0，分行科技0.95，外包1.10）
- PF_scope：范围变更因子（无变更1.0，小幅变更1.05，重大变更1.15）

#### 方法二：基于CPI和SPI的ETC估算（适用于成本和进度双重超支）

```
ETC = (BAC - EV) / (CPI × SPI)
```

**适用条件**：成本和进度均超支（ CPI < 1 且 SPI < 1）

**典型绩效因子调整**：
```
CPI_SPI_adjusted = (CPI × SPI) × PF_combined
PF_combined = 0.90 × PF_complexity × PF_resource × PF_schedule
```

其中：
- PF_schedule：进度压力因子（正常1.0，年底冲刺0.98，监管窗口1.05）

#### 方法三：基于典型绩效因子的ETC估算（适用于银行项目标准）

```
ETC = (BAC - EV) / TCPI
TCPI = (BAC - EV) / (BAC - AC)
```

**适用条件**：项目进入后半程，需按当前绩效预测最终成本

### 2.3 完工估算（EAC）公式

| 方法 | 公式 | 说明 |
|------|------|------|
| 方法一 | EAC = AC + ETC | 基于当前成本效率 |
| 方法二 | EAC = BAC / CPI | 成本超支按当前效率延续 |
| 方法三 | EAC = AC + (BAC - EV) / (CPI × SPI) | 双重绩效因子 |
| 方法四 | EAC = BAC - CV | 不考虑未来绩效变化 |

**推荐方法**：银行项目优先使用**方法三**，综合考虑成本和进度绩效。

## 3. EVM偏差分析框架

### 3.1 偏差等级划分

| 等级 | CPI范围 | SPI范围 | 风险级别 | 处理要求 |
|------|---------|---------|----------|----------|
| 绿色 | ≥ 0.95 | ≥ 0.95 | 低风险 | 正常监控 |
| 黄色 | 0.85 ~ 0.95 | 0.85 ~ 0.95 | 中风险 | 增加监控频次 |
| 橙色 | 0.70 ~ 0.85 | 0.70 ~ 0.85 | 高风险 | 提交SCCB审批 |
| 红色 | < 0.70 | < 0.70 | 严重风险 | 立即上报，启动应急 |

### 4.1 ETC重新估算标准流程

```
1. 数据收集
   ├─ 1.1 获取项目基线数据（baseline_budget, baseline_schedule）
   ├─ 1.2 收集当前周期EVM数据（PV, EV, AC）
   ├─ 1.3 获取历史EVM数据（至少最近3期）
   └─ 1.4 确认绩效因子取值

2. 指标计算
   ├─ 2.1 计算成本偏差 CV = EV - AC
   ├─ 2.2 计算进度偏差 SV = EV - PV
   ├─ 2.3 计算成本绩效指数 CPI = EV / AC
   ├─ 2.4 计算进度绩效指数 SPI = EV / PV
   └─ 2.5 确定风险等级

3. ETC估算
   ├─ 3.1 根据CPI和SPI组合选择估算方法
   │   ├─ CPI ≥ 0.9 且 SPI ≥ 0.9 → 方法一
   │   ├─ CPI < 0.9 或 SPI < 0.9 → 方法二
   │   └─ 项目进度 > 60% → 方法三
   ├─ 3.2 套用典型绩效因子进行调整
   ├─ 3.3 计算ETC值
   └─ 3.4 计算EAC值

4. 偏差分析
   ├─ 4.1 识别偏差类型（成本偏差/进度偏差/双重偏差）
   ├─ 4.2 分析偏差原因（需求变更/资源不足/技术问题/外部因素）
   ├─ 4.3 评估偏差影响（范围/进度/成本/质量）
   └─ 4.4 生成偏差分析报告

5. SCCB审批包生成
   ├─ 5.1 编制重估算申请报告
   ├─ 5.2 准备偏差分析说明
   ├─ 5.3 制定纠偏措施计划
   ├─ 5.4 更新项目基线（如需）
   └─ 5.5 生成完整审批包

6. 审批与跟踪
   ├─ 6.1 提交SCCB审批
   ├─ 6.2 记录审批结论
   ├─ 6.3 更新项目管控台账
   └─ 6.4 跟踪纠偏措施执行
```

### 4.2 紧急重新估算流程

**触发条件**：橙色或红色风险等级

```
1. 立即上报项目经理和PMO
2. 启动偏差根因分析（48小时内完成初步分析）
3. 制定应急纠偏方案
4. 提交SCCB紧急审批（绿色通道）
5. 执行纠偏措施
6. 每周期跟踪汇报
```

### 4.3 分行科技项目简化流程

**适用范围**：预算小于500万元、工期小于6个月的分行科技项目

```
1. 收集简化EVM数据（仅需EV和AC）
2. 计算简化CPI = EV / AC
3. 应用固定绩效因子（PF_bank = 1.0）
4. 计算ETC = (BAC - EV) / CPI
5. 填写简化版SCCB申请
6. 提交分行科技部门审批
```

## 6. 典型应用场景

### 6.1 核心系统改造项目

**项目特征**：预算5000万+，工期18个月+，跨部门协作

**ETC估算方法**：方法二（基于CPI×SPI）

**典型绩效因子**：
```
PF_bank = 0.95 × 1.15 × 1.00 × 1.05 = 1.1606
```

### 6.2 支付通道接入项目

**项目特征**：预算2000万，工期12个月，涉及多方对接

**ETC估算方法**：方法三（基于TCPI）

**典型绩效因子**：
```
PF_bank = 0.95 × 1.10 × 1.05 × 1.00 = 1.0993
```

### 6.3 分行科技建设项目

**项目特征**：预算300万，工期6个月，本地实施

**ETC估算方法**：简化流程

**典型绩效因子**：
```
PF_bank = 1.0（使用固定值）
```

- 变更原因分类（需求变更、资源调整、技术问题、外部因素）

## 8. 合规说明

1. **监管要求**：银行IT项目 ETC 重新估算需符合银保监会相关监管要求
2. **审批权限**：超过基线预算10%的重估算需提交总行SCCB审批
3. **档案管理**：所有重估算记录和审批材料保留不少于10年
4. **定期审计**：PMO每季度对重估算准确性进行审计
5. **问责机制**：重大偏差需追溯原因，明确责任

## Quality Gates
