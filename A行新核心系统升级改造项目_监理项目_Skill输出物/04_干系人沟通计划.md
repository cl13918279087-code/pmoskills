### 1.2 Power/Interest Grid

```
                        高权力
                           │
          ┌────────────────┼────────────────┐
          │                │                │
    B     │   C           │       A        │
  (Keep   │  (Keep        │  (Manage      │
  Satisfied)│  Informed)   │   Closely)    │
          │                │                │
          │ 外部审计       │  张三(CIO)     │ ←A区：月度书面简报+专题汇报

          │               │  项目指导委员会  │ ←A区：月度书面简报+里程碑汇报
          │               │  PMO           │ ←A区：双周简报+日常沟通
          │               │                │
          │                │                │
    D     │                │                │
  (Monitor)│               │                │
          │ 实施商（非核心│               │
          │ 成员）、行政   │               │
          │ 后勤人员       │               │
          │               │                │
          └────────────────┼────────────────┘
                           │
                        低权力
                          高利益←————→低利益
```

| 区域 | 干系人 | 沟通策略 |
|------|--------|---------|
| A区（高权力/高利益） | 张三、李四、项目指导委员会、PMO | **Manage Closely**：月度书面简报+专题汇报+重大事项即时升级 |
| B区（高权力/低利益） | 外部审计、母公司CFO | **Keep Satisfied**：季度总结报告，避免过度沟通 |
| C区（低权力/高利益） | 总体项目组、需求分析组、架构设计组、测试管理组、开发实施组 | **Keep Informed**：周例会+工作邮件+即时通讯 |
| D区（低权力/低利益） | 实施商（非核心成员）、行政后勤人员 | **Monitor**：月度摘要邮件，无重大更新可跳过 |

## 5. 升级协议

### 5.1 RAG定义

| 等级 | 定义 | 沟通时限 |
|------|------|---------|
| 🔴 Red | 监管行动、数据泄露、预算超支>15%、进度延误>4周 | 立即（2小时内）口头通知，24小时内书面报告 |
| 🟠 Amber | 关键人员离职、供应商履约不力、范围蔓延>10% | 48小时内书面通知 |
| 🟢 Green | 在容差范围内跟踪，无重大问题 | 周报中例行汇报 |

### 5.2 升级路径

```
问题识别 → 项目经理 → PMO经理 → 我司项目总监 → 项目指导委员会
                           ↓（合规/监管相关）
                     合规总监 → 监管机构（如需）
```

## 6. 沟通约束

| 约束类型 | 具体要求 | 责任方 |
|---------|---------|--------|
| 信息保密 | 涉及监管数据、财务预测的沟通需审批 | PMO+行方保密办 |
| 监管沟通 | 对银保监/人行的正式回复须经合规部门 | 合规部门 |
| 客户数据 | 任何沟通中涉及客户信息需数据办公室审查 | 行方数据办公室 |
| 供应商合同 | 涉及合同条款和价格的沟通需采购部门参与 | 行方采购部 |
