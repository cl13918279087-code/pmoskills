## Purpose

会议纪要是项目管理的重要沟通 artifact，它不仅是会议内容的记录，更是项目决策、任务分配和问题跟踪的核心载体。本技能指导如何高效记录、组织、分发和管理会议纪要，确保会议决议得到有效执行和闭环跟踪。

**本技能适用于所有项目会议类型：**
- 项目启动会
- 周/月例会
- 阶段性汇报会
- 专题研讨会
- 需求评审会
- 设计评审会
- 上线评审会
- 项目收尾会

## When to use
## Trigger this skill when

- 项目启动后需要建立会议管理机制
- 团队需要统一的会议纪要格式和流程
- 会议决议执行情况需要跟踪闭环
- 需要将会议决策转化为可执行的任务
- 项目沟通需要留下正式记录

## Meeting Types and Their Focus

### 1. 项目启动会 (Project Kickoff Meeting)

| 要素 | 内容要求 |
|------|----------|
| 目的 | 正式宣布项目启动，统一团队目标，建立沟通机制 |
| 核心内容 | 项目背景、目标、范围、组织架构、初步计划、沟通机制 |
| 参会人 | 全体项目成员、项目管理委员会成员 |
| 输出重点 | 项目目标共识、角色职责确认、沟通计划 |

### 2. 周/月例会 (Regular Status Meeting)

| 要素 | 内容要求 |
|------|----------|
| 目的 | 同步进度、识别问题、协调资源、跟踪行动项 |
| 核心内容 | 上期行动项完成情况、本期工作进展、问题与风险、下期计划 |
| 参会人 | 项目经理、全体执行成员 |
| 输出重点 | 进度状态、行动项清单、问题升级 |

### 3. 阶段性评审会 (Phase Review Meeting)

| 要素 | 内容要求 |
|------|----------|
| 目的 | 评审阶段成果，确认是否可以进入下一阶段 |
| 核心内容 | 阶段交付物评审、目标达成情况、变更评审、风险重评估 |
| 参会人 | PMO、业务代表、技术负责人、质量管理组 |
| 输出重点 | 阶段验收结论、遗留问题、下阶段准入条件 |

### 4. 专题会议 (Ad-hoc Meeting)

| 要素 | 内容要求 |
|------|----------|
| 目的 | 解决特定问题或讨论专项议题 |
| 核心内容 | 问题描述、方案讨论、决策结论、任务分配 |
| 参会人 | 相关专题负责人和决策人 |
| 输出重点 | 问题和解决方案、明确的执行计划 |

### 5. 监管报送协调会 (Regulatory Submission Coordination Meeting)

| 要素 | 内容要求 |
|------|----------|
| 目的 | 协调银保监/央行监管数据报送的时间、内容、分工与口径一致性 |
| 核心内容 | 报送清单确认、数据口径核对、系统取数逻辑评审、报送时间节点对齐 |
| 参会人 | 科技部、数据团队、合规部、业务部门、外包厂商 |
| 输出重点 | 报送任务分解表、数据责任矩阵、截止时间确认 |
| 监管场景 | 1104报表报送EAST系统对账、人行金融基础数据报送、反洗钱大额交易报送 |

### 6. 信息科技风险管理委员会会议 (IT Risk Committee Meeting)

| 要素 | 内容要求 |
|------|----------|
| 目的 | 向风险管理委员会汇报信息科技风险状况，获取决策支持 |
| 核心内容 | 风险热图更新、重大风险事件、风险缓释措施进展、监管检查发现问题整改进展 |
| 参会人 | 首席信息官(CIO)、风险管理部负责人、合规负责人、内审、PMO |
| 输出重点 | 风险决策记录、风险缓释任务、下一汇报周期重点关注项 |
| 监管场景 | 《银行保险机构信息科技风险管理指引》要求的信息科技风险定期汇报 |

### 7. 项目里程碑验收会 (Milestone Acceptance Meeting)

| 要素 | 内容要求 |
|------|----------|
| 目的 | 正式确认里程碑交付物完成，可进入下一阶段 |
| 核心内容 | 交付物清单核对、质量门通过情况、遗留问题清单、验收结论 |
| 参会人 | 业务验收代表、技术负责人、PMO、质量管理组 |
| 输出重点 | 里程碑验收报告、遗留问题处理计划、下一里程碑计划 |

### 8. 董事会/高管专题汇报会 (Executive Briefing)

| 要素 | 内容要求 |
|------|----------|
| 目的 | 向董事会或高管层汇报重大项目进展或重大变更决策 |
| 核心内容 | 项目战略价值回顾、当前进度与偏差、变更请求、所需资源/预算审批 |
| 参会人 | 行长/分管副行长、首席信息官、首席财务官、董事会秘书 |
| 输出重点 | 决策备忘录、高管审批纪要、资源调配指令 |
| 监管场景 | 超过集中度上限的重大项目投资审批、大规模系统升级向监管的事前报告 |

## Procedure

> This skill follows the **Action Item Tracking Process** defined above. Execute: 会前确认议程 → 会中记录要点 → 会后整理纪要 → 分发确认 → 跟踪行动项闭环.

### Lifecycle

```
创建 → 分发 → 执行跟踪 → 完成确认 → 闭环归档
```

### Tracking Table Format

| 行动项ID | 会议纪要编号 | 行动项描述 | 责任人 | 协助人 | 计划完成日 | 实际完成日 | 状态 | 完成证据 |
|----------|--------------|------------|--------|--------|------------|------------|------|----------|
| AI-001 | MN-2024-001 | 完成需求文档编写 | 张三 | 李四 | 2024-03-20 | 2024-03-19 | 已完成 | 需求文档V1.2 |

### Status Definitions

| 状态 | 定义 | 颜色标识 |
|------|------|----------|
| 待开始 | 已分配，尚未开始执行 | 🔴 红 |
| 进行中 | 正在执行中 | 🟡 黄 |
| 已完成 | 任务完成并通过确认 | 🟢 绿 |
| 已延期 | 超过计划完成时间未完成 | ⚠️ 橙 |
| 已取消 | 因客观原因取消 | ⚪ 灰 |

### Follow-up Mechanisms

| 跟踪方式 | 频率 | 责任人 | 内容 |
|----------|------|--------|------|
| 周报更新 | 每周 | 行动项负责人 | 更新各项状态 |
| 例会通报 | 每周例会 | 项目经理 | 通报完成情况，识别阻塞 |
| 邮件提醒 | 计划完成日前3天 | 记录人 | 自动提醒责任人 |
| 升级机制 | 超期2天以上 | 项目经理 | 升级至相关管理层 |

### Banking-Specific Escalation Matrix (银行业行动项升级矩阵)

行动项超期后，按以下矩阵逐级升级：

| 超期时长 | 升级对象 | 升级方式 | 行动 |
|----------|----------|----------|------|
| 1-2天 | 直接上级（项目经理） | 邮件/即时通讯 | 督促加快执行，确认新的完成时间 |
| 3-5天 | PMO负责人 | 正式邮件 | 发出预警通知，评估对里程碑影响 |
| 6-10天 | 项目管理委员会(SCCB) | 例会/专题汇报 | 讨论是否需要变更计划/追加资源/调整范围 |
| 10天以上 | 行长/分管副行长 | 签报 | 提交决策审批，明确责任追究 |

**监管类行动项（如监管检查整改、数据报送修复）超期一律直接升级至PMO负责人+合规部门，24小时内必须处理，不得按普通行动项逐级升级。**

## Quality Gates

| # | 检查项 | 验证标准 |
|---|--------|----------|
| 1 | 完整性 | 包含所有标准章节，无遗漏 |
| 2 | 准确性 | 决议和行动项描述清晰、无歧义 |
| 3 | 可执行性 | 每项行动项有明确责任人和完成时间 |
| 4 | 及时性 | 会议结束后24小时内发出初稿 |
| 5 | 跟踪性 | 上期行动项完成情况在本期纪要中更新 |
| 6 | 分发适当 | 仅发给相关人员，符合保密级别 |

## Best Practices

### Do's ✅

- 会议开始前准备标准模板
- 录音备份（需征得参会人同意）
- 使用统一的编号规则（MN-YYYY-NNN）
- 行动项描述使用"动词+名词+标准"格式
- 及时更新上期行动项状态
- 会议结束前确认决议和行动项

### Don'ts ❌

- 不要遗漏任何参会人的发言要点
- 不要使用模糊的责任人（如"项目组"）
- 不要设置模糊的完成时间（如"尽快"）
- 不要在纪要中记录与议题无关的内容
- 不要让纪要成为唯一的沟通渠道

## Failure Modes to Avoid

| 失败模式 | 说明 | 应对 |
|----------|------|------|
| ❌ 纪要不完整 | 遗漏重要决议或行动项 | 使用标准模板，检查清单 |
| ❌ 责任人不明确 | "项目组"而非具体人 | 必须指定到具体姓名 |
| ❌ 无人跟踪 | 发出后无人跟进执行 | 指定专人负责跟踪 |
| ❌ 分发范围不当 | 该知道的人没收到 | 建立并维护分发清单 |
| ❌ 更新不及时 | 行动项状态长期不更新 | 例会必须更新，定期邮件提醒 |
