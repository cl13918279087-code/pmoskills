## Purpose

项目文档模板是确保项目信息一致性和质量的基础工具。本技能指导如何建立、分类、维护和优化项目文档模板库，使项目团队能够快速产出符合规范的文档，减少格式错误，提升文档质量。

**本技能适用于：**
- 新项目启动时建立模板体系
- 现有模板体系的优化和扩展
- 跨项目模板标准化
- 模板版本管理和控制

## When to use
## When to use this skill

本技能在以下场景触发：
- 新项目启动，需要建立文档模板体系
- 现有模板分散或格式不统一
- 需要确保跨项目文档一致性
- 项目文档质量需要提升
- 需要建立模板版本控制机制

## Procedure

This skill manages the template library lifecycle in 4 steps:

**Step 1: Template Library Maintenance**
- Keep the Template Index (Section 7) current with all available templates
- Ensure each template has version number, owner, and last-updated date

**Step 2: Template Version Control**
- Follow Template Version Control process for all changes
- Never overwrite a published version; create new versions with incrementing numbers
- Retire outdated templates with clear deprecation notice

**Step 3: Template Recommendation**
- Match user needs against the Template Index based on project type and phase
- Provide template with version number and usage guidance
- When no exact match exists, recommend the closest available template with adaptation notes

**Step 4: Feedback Collection and Iteration**
- Collect usage feedback after each template is deployed
- Log feedback in the Template Quality Checklist (Section 6)
- Update templates in the next version cycle based on feedback

| 类别代码 | 类别名称 | 说明 |
|----------|----------|------|
| RSK-TECH | 技术风险 | 技术选型、实现难度、技术成熟度 |
| RSK-BUSI | 业务风险 | 需求变化、业务流程、用户接受度 |
| RSK-ORGA | 组织风险 | 资源不足、团队协作、沟通障碍 |
| RSK-EXTE | 外部风险 | 法规变化、供应商、市场环境 |
| RSK-FINA | 财务风险 | 预算超支、成本控制、投资回报 |
| RSK-SCHE | 进度风险 | 延期、依赖关系、资源冲突 |

## 风险值计算

```
风险值 = 影响程度 × 发生概率

影响程度：高中低 = 3/2/1
发生概率：高中低 = 3/2/1

风险值范围：
- 7-9：高风险（红色）- 需要立即关注和应对
- 4-6：中风险（黄色）- 需要制定应对计划
- 1-3：低风险（绿色）- 可接受水平
```

## 应对策略说明

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 规避 | 消除风险源 | 风险高且可避免 |
| 转移 | 将风险转移给第三方 | 财务风险、保险、外包 |
| 减轻 | 降低风险概率或影响 | 技术风险、进度风险 |
| 接受 | 承认风险存在，准备应急 | 低风险或不可控风险 |

## Best Practices

### Do's ✅

- 模板发布前经过评审和试用
- 为每个字段提供填写说明或示例
- 模板编号与文档编号规则一致
- 定期回顾模板使用情况，收集改进意见
- 建立模板审批和发布的标准流程
- 保持模板库的版本更新记录

### Don'ts ❌

- 不要创建过于复杂的模板
- 不要让模板限制合理的创新
- 不要忽视用户反馈
- 不要混用不同版本的模板
- 不要在没有审批的情况下发布新模板

## Failure Modes to Avoid

| 失败模式 | 说明 | 应对 |
|----------|------|------|
| ❌ 模板过于复杂 | 填写困难导致使用率低 | 简化模板，突出核心字段 |
| ❌ 版本混乱 | 多版本同时使用 | 严格执行版本回收 |
| ❌ 与实际脱节 | 模板不适应项目实际 | 定期评审和更新 |
| ❌ 无审批流程 | 随意修改模板 | 建立变更审批机制 |
| ❌ 缺乏培训 | 用户不知道如何正确使用 | 提供模板使用培训 |
