## 目的

## Purpose

> **EN Alias / 英文别名**: `## Purpose` — 本章节英文版本

聚合项目多维度数据（进度、问题、风险、资源、质量），按标准化报告模板填充内容，生成格式化的项目报告（周报/月报/专题报告）；对数据进行准确性校验，确保报告真实准确；管理报告分发，确保相关方及时收到报告并知晓内容。

## 触发时机

## When to use

> **EN Alias / 英文别名**: `## When to use` — 本章节英文版本

- 项目周期性的报告节点（每周五/每月末）
- 项目进入关键里程碑，需要专项汇报
- 项目出现重大问题或风险，需要升级汇报
- 高层或相关方临时要求提供项目状态报告
- 项目阶段转换（规划→执行/执行→监控/监控→收尾）
- 项目需要对外汇报（向客户、监管机构、合作伙伴）
- PMO或项目管理委员会要求提交标准格式报告

## 报告类型框架

### 1. 周报（Weekly Report）

| 章节 | 内容要点 | 数据来源 |
|------|----------|----------|
| 本周进展 | 本周完成的工作、里程碑达成情况 | 任务完成记录、会议纪要 |
| 下周计划 | 计划开展的工作、预期成果 | 项目计划、周粒度任务 |
| 问题风险 | 本周新增问题/风险、处置情况 | 问题日志、风险登记册 |
| 资源状态 | 人员投入、资源使用情况 | 工时记录、资源使用报告 |
| 变更记录 | 本周发生的变更及影响 | 变更日志 |
| 附件清单 | 本周交付物、评审记录等 | 交付物清单 |

### 2. 月报（Monthly Report）

| 章节 | 内容要点 | 数据来源 |
|------|----------|----------|
| 执行摘要 | 本月项目整体状态（一段话概括） | 项目综合数据 |
| 关键指标 | 进度偏差、成本偏差、质量指标、风险指标 | 挣值数据、质量数据 |
| 里程碑状态 | 各里程碑达成情况、偏差分析 | 里程碑跟踪表 |
| 进展详情 | 各模块/子系统进展 | 任务完成情况 |
| 问题风险汇总 | 本月问题/风险汇总及趋势分析 | 问题日志、风险登记册 |
| 资源投入 | 人员投入、设备投入、费用支出 | 工时统计、费用报销 |
| 变更汇总 | 本月变更汇总及累计变更情况 | 变更日志 |
| 下月计划 | 下月重点工作、里程碑安排 | 项目计划 |
| 附件清单 | 本月交付物清单、重大决策记录 | 交付物清单、会议纪要 |

### 3. 专题报告（Special Report）

| 报告类型 | 适用场景 | 重点内容 |
|----------|----------|----------|
| 里程碑报告 | 关键里程碑达成后 | 里程碑达成情况、验收结果、下阶段计划 |
| 问题升级报告 | 重大问题需要升级时 | 问题详情、影响分析、解决方案、决策请求 |
| 风险预警报告 | 高风险需要关注时 | 风险详情、影响评估、应对措施、资源请求 |
| 变更影响报告 | 重大变更审批前 | 变更内容、影响分析、备选方案、建议 |
| 阶段总结报告 | 项目阶段转换时 | 本阶段总结、下阶段计划、资源需求 |
| 项目收尾报告 | 项目验收时 | 项目成果、交付物清单、经验教训、遗留项 |

### 4. 监管报送报告（Regulatory Submission Report）

|| 章节 | 内容要点 | 数据来源 |
|------|----------|----------|
| 报送基本信息 | 报送批次号、报送日期、监管机构、数据口径版本 | 报送任务单 |
| 监管指标数据 | 各监管指标值、计算口径、取数来源 | 业务系统、数据仓库 |
| 异常数据标注 | 异常波动数据、与上期差异超阈值数据、与预期不符数据 | 自动校验报告 |
| 合规判断 | 数据是否符合监管要求（达标/预警/违规） | 合规检查规则 |
| 整改计划 | 异常数据的整改措施、预计完成时间 | 整改任务清单 |
| 报送人确认 | 报送人、数据负责人、合规确认人签字 | 报送确认单 |

适用场景：《1104非现场监管报表》月度报送、《EAST系统对账报告》、人行《金融基础数据统计》报送、银保监会《信息科技风险监管报表》报送。

### 5. 董事会/高管专题汇报（Executive Report）

|| 章节 | 内容要点 | 受众 |
|------|----------|------|
| 项目战略价值回顾 | 项目与全行科技战略对齐情况、对业务发展的支撑作用 | 行长、董事会 |
| 投资回报分析 | 项目预算执行情况、投资回报预期、与批复方案的偏差 | 行长、CFO |
| 里程碑达成情况 | 关键里程碑进展、对全行系统上线计划的影响 | 行长、CIO |
| 重大风险预警 | 超过风险容忍度的风险、监管合规风险 | 行长CRO |
| 资源需求与决策 | 追加预算、延期审批、跨部门资源协调 | 行长决策层 |
| 监管沟通情况 | 监管检查发现、整改进展、监管关系维护 | 行长、合规 |

### 6. 信息科技风险定期报告（IT Risk Periodic Report）

|| 报告类型 | 报告周期 | 重点内容 |
|----------|----------|----------|
| 信息科技风险月报 | 每月 | 系统运行指标、安全事件、风险变化趋势 |
| 信息科技风险季报 | 每季 | 全面风险评估、风险缓释进展、监管合规状态 |
| 信息科技风险年度报告 | 每年 | 年度风险回顾、重大风险事件、下一年度风险规划 |
| 监管检查整改报告 | 按需 | 监管检查发现的问题、整改措施、责任追究 |

适用于《银行保险机构信息科技风险管理指引》规定的定期风险汇报要求。

## 数据准确性校验

### 校验维度

| 校验项 | 校验方法 | 异常处理 |
|--------|----------|----------|
| 数据完整性 | 检查必填字段是否有值 | 标注缺失项，联系数据提供方补充 |
| 数据一致性 | 跨表格数据是否一致（如进度与工时） | 识别不一致点，追溯原因并修正 |
| 数据时效性 | 数据是否在报告周期内 | 标注过期数据，说明数据截止时间 |
| 数据合理性 | 数据是否在合理范围内 | 异常值标注，分析原因 |
| 数据逻辑性 | 数据关系是否符合业务逻辑 | 逻辑校验，异常提示 |

### 校验流程

```
1. 数据采集
   ├─ 从各数据源采集原始数据
   ├─ 记录数据采集时间和数据负责人
   └─ 建立数据采集清单

2. 数据清洗
   ├─ 剔除明显错误数据
   ├─ 处理缺失数据（标注或估算）
   └─ 标准化数据格式

3. 数据校验
   ├─ 执行完整性校验
   ├─ 执行一致性校验
   ├─ 执行合理性校验
   └─ 输出校验报告

4. 数据确认
   ├─ 数据提供方确认数据准确性
   ├─ 项目经理确认数据完整性
   └─ 签字确认后进入报告生成

5. 报告生成
   ├─ 按模板填充数据
   ├─ 生成图表和分析
   └─ 输出报告初稿

6. 报告审核
   ├─ 自查报告内容
   ├─ 项目经理审核
   ├─ 相关方确认（如需要）
   └─ 批准发布
```

## Procedure

### Step 1: 报告准备

```
1.1 明确报告要求
    ├─ 确定报告类型（周报/月报/专题报告）
    ├─ 确定报告周期和提交时间
    ├─ 确定报告模板和格式要求
    └─ 确定报告审批流程

1.2 收集干系人信息
    ├─ 确认报告分发对象（主送/抄送）
    ├─ 了解各干系人关注重点
    ├─ 确认报告语言和详细程度
    └─ 准备沟通渠道（邮件列表、会议安排）

1.3 准备数据采集
    ├─ 确定数据来源（任务系统/工时系统/风险系统）
    ├─ 准备数据采集表或自动化脚本
    ├─ 联系数据提供方确认数据就绪
    └─ 确定数据截止时间
```

### Step 2: 数据采集与校验

```
2.1 采集项目数据
    ├─ 采集进度数据（任务完成、里程碑状态）
    ├─ 采集问题数据（新增/处理中/已关闭）
    ├─ 采集风险数据（新增/变化/已缓解）
    ├─ 采集资源数据（工时投入、人员状态）
    └─ 采集质量数据（缺陷统计、测试通过率）

2.2 执行数据校验
    ├─ 完整性校验（必填字段检查）
    ├─ 一致性校验（跨数据源一致性）
    ├─ 时效性校验（数据在有效期内）
    ├─ 合理性校验（数据值在合理范围）
    └─ 输出校验异常报告

2.3 数据确认与修正
    ├─ 与数据提供方确认异常数据
    ├─ 追溯数据源头修正错误
    ├─ 对无法修正的数据标注说明
    └─ 完成数据确认签字
```

### Step 3: 报告生成

```
3.1 按模板生成报告
    ├─ 填充报告基础信息（项目名称、报告周期等）
    ├─ 填充进度数据（本周/本月进展）
    ├─ 填充问题风险数据（汇总和分析）
    ├─ 填充资源数据（投入和分析）
    ├─ 填充质量数据（如有）
    └─ 填充下期计划数据

3.2 数据可视化
    ├─ 生成进度趋势图
    ├─ 生成问题风险趋势图
    ├─ 生成资源投入图
    ├─ 生成关键指标仪表盘
    └─ 生成对比分析图（计划vs实际）

3.3 报告撰写
    ├─ 撰写执行摘要（项目整体状态）
    ├─ 撰写进展分析（关键发现和亮点）
    ├─ 撰写问题风险分析（需要关注的事项）
    ├─ 撰写趋势预测（预判下期情况）
    └─ 撰写建议措施（需要采取的行动）

3.4 报告审核
    ├─ 自查报告内容完整性和准确性
    ├─ 项目经理审核并修改
    ├─ 关键干系人确认（如需要）
    └─ 批准发布
```

### Step 4: 报告分发

```
4.1 确认分发清单
    ├─ 按干系人列表确认分发对象
    ├─ 区分主送和抄送对象
    ├─ 确认分发方式和格式（邮件/系统/纸质）
    └─ 准备报告分发说明

4.2 执行报告分发
    ├─ 生成最终报告文件
    ├─ 按分发清单发送报告
    ├─ 附带阅读说明和反馈要求
    └─ 记录分发时间和方式

4.3 跟踪阅读确认
    ├─ 跟踪关键干系人阅读情况
    ├─ 对未阅读的干系人进行提醒
    ├─ 收集干系人反馈意见
    └─ 记录反馈情况

4.4 归档报告
    ├─ 按归档要求保存报告
    ├─ 在项目文档管理系统中登记
    ├─ 更新报告索引和清单
    └─ 通知需要查阅的人员归档位置
```

## Quality Gates

| # | 检查项 | 检查标准 | 检查方法 |

## 失败模式规避

| 失败模式 | 描述 | 应对措施 |
|----------|------|----------|
| 数据不准确 | 报告数据与实际情况不符 | 建立数据校验机制；数据提供方签字确认 |
| 数据不及时 | 数据采集延误影响报告提交 | 提前启动数据采集；自动化数据采集 |
| 报告内容空洞 | 报告只有数据罗列，没有分析 | 明确分析要求；提供分析框架模板 |
| 分发不完整 | 部分干系人未收到报告 | 建立分发清单管理；发送后确认机制 |
| 报告延迟 | 报告未能按时提交 | 设定报告生成时间表；预留缓冲时间 |
| 报告格式不统一 | 不同项目报告格式差异大 | 统一报告模板；定期检查格式执行 |
| 经验未积累 | 报告质量问题重复出现 | 建立报告质量评估；定期复盘改进 |
