compliance-check

## 目的

确定项目管理制度和合规标准，建立检查清单，按周期执行合规性检查，记录检查结果，识别不符合项，推动整改，跟踪整改完成情况，输出合规总结报告，确保项目执行符合组织规范和监管要求。

## Purpose

（见 ## 目的）

合规检查 Skill 为项目提供标准化合规性审查能力，确保项目执行过程符合监管要求、行业标准及内部制度，降低合规风险，满足审计追踪要求。
## When to use
## When to use this skill

（见 ## 触发时机）

## 触发时机

- 项目进入执行阶段，需要建立合规检查机制
- 定期合规检查周期（每月/每季度）
- 项目进入关键里程碑前，需要进行合规预检
- 监管要求的外审/内审检查前
- 项目出现合规问题或违规事件后
- 项目经理或PMO发起的专项合规检查
- 新制度/标准发布后，需要验证执行情况

## 合规检查维度框架

### 1. 项目管理合规检查

| 检查领域 | 检查内容 | 检查标准 |
|----------|----------|----------|
| 计划管理 | 项目计划制定、跟踪、变更控制 | 计划完整性、跟踪及时性、变更合规性 |
| 进度管理 | 进度计划执行、偏差分析、进度报告 | 里程碑达成率、进度偏差在可控范围 |
| 成本管理 | 成本预算、控制、费用报销 | 预算执行率、成本偏差在可控范围 |
| 质量管理 | 质量计划、质量保证、质量控制 | 质量活动执行率、缺陷修复及时性 |
| 风险管理 | 风险识别、评估、应对、监控 | 风险覆盖度、应对措施有效性 |
| 沟通管理 | 沟通计划执行、报告分发、会议管理 | 沟通频次、报告及时性、会议纪要 |

### 2. 过程合规检查

| 检查领域 | 检查内容 | 检查标准 |
|----------|----------|----------|
| 决策合规 | 重大决策是否按程序审批 | 决策审批记录、决策依据完整性 |
| 变更合规 | 变更是否按流程审批 | 变更申请、评估、审批记录完整 |
| 采购合规 | 采购流程是否合规 | 供应商选择、合同审批流程合规 |
| 文档合规 | 文档是否按要求编写和归档 | 文档完整性、规范性、归档及时性 |
| 验收合规 | 验收流程是否合规 | 验收标准、验收记录、签字完整性 |

### 3. 安全管理合规检查

| 检查领域 | 检查内容 | 检查标准 |
|----------|----------|----------|
| 信息安全 | 信息安全措施执行情况 | 安全策略执行、安全培训、事件处理 |
| 访问控制 | 账号权限管理是否合规 | 权限最小化、定期复核、离场处理 |
| 数据安全 | 数据保护措施是否到位 | 敏感数据加密、数据备份、数据泄露防护 |
| 物理安全 | 物理环境安全措施 | 门禁、监控、设备安全管理 |

### 4. 监管合规检查

| 检查领域 | 检查内容 | 检查标准 |
|----------|----------|----------|
| 监管报送 | 监管数据报送是否及时准确 | 报送时限、数据准确性、完整性 |
| 监管配合 | 配合监管检查情况 | 检查配合、问题整改、报告提交 |
| 合规档案 | 合规档案是否完整 | 档案完整性、可追溯性、保存期限 |

## Procedure
### Step 1: 检查准备

```
1.1 明确检查范围和目标
    ├─ 确定检查的项目和业务范围
    ├─ 确定检查的领域和重点
    ├─ 确定检查的标准和依据
    └─ 确定检查的参与人员

1.2 收集检查依据
    ├─ 收集适用的管理制度和标准
    ├─ 收集适用的监管要求和合规规范
    ├─ 收集历史检查记录和整改情况
    └─ 收集项目相关背景材料

1.3 制定检查计划
    ├─ 制定检查时间计划
    ├─ 安排检查人员和分工
    ├─ 准备检查工具和模板
    └─ 通知被检查方检查安排

1.4 组建检查组
    ├─ 确定检查组长
    ├─ 确定各领域检查员
    ├─ 确定检查秘书（记录）
    └─ 对检查员进行培训（如需要）
```

### Step 2: 执行检查

```
2.1 文档检查
    ├─ 检查项目文档的完整性和规范性
    ├─ 验证制度文件的版本和更新情况
    ├─ 核对记录文档的及时性和完整性
    └─ 检查文档归档的规范性

2.2 流程检查
    ├─ 验证关键流程的执行情况
    ├─ 抽查流程执行的证据（记录、签字）
    ├─ 验证流程变更的合规性
    └─ 识别流程执行偏差

2.3 现场检查
    ├─ 现场访谈相关人员
    ├─ 观察实际操作流程
    ├─ 验证系统配置和权限设置
    └─ 抽查实际执行情况

2.4 数据检查
    ├─ 核对数据的准确性和一致性
    ├─ 验证数据的完整性和及时性
    ├─ 检查数据报送的合规性
    └─ 抽查数据的可追溯性

2.5 记录检查结果
    ├─ 记录每项检查的执行情况
    ├─ 记录检查发现（合格/不合格/待观察）
    ├─ 记录不符合项的详细描述
    └─ 收集检查证据（截图、文件摘录）
```

### Step 3: 问题分析与整改

```
3.1 问题汇总与分析
    ├─ 汇总所有检查发现的符合项
    ├─ 汇总所有检查发现的不符合项
    ├─ 分析不符合项的根本原因
    ├─ 评估不符合项的影响程度
    └─ 确定不符合项的优先级

3.2 制定整改计划
    ├─ 针对每个不符合项制定整改措施
    ├─ 明确整改责任人
    ├─ 确定整改完成时间
    ├─ 制定整改验证方式
    └─ 评审整改计划的可行性和充分性

3.3 推动整改执行
    ├─ 向被检查方通报检查结果
    ├─ 下发整改通知
    ├─ 跟踪整改进度
    ├─ 提供整改指导（如需要）
    └─ 收集整改证据

3.4 整改验证
    ├─ 验证整改措施是否已执行
    ├─ 验证整改效果是否达到要求
    ├─ 确认不符合项已关闭
    └─ 记录验证结果
```

### Step 4: 报告输出

```
4.1 编写合规检查报告
    ├─ 汇总检查范围和检查方法
    ├─ 汇总检查总体情况（符合率等）
    ├─ 详细描述不符合项（按领域分类）
    ├─ 分析不符合项的原因和影响
    ├─ 汇总整改情况
    └─ 提出改进建议

4.2 报告评审与发布
    ├─ 检查组内部评审报告
    ├─ 向被检查方确认事实
    ├─ 提交报告审批
    └─ 发布报告并分发

4.3 归档与跟踪
    ├─ 归档检查材料（检查清单、记录、证据）
    ├─ 归档报告和整改记录
    ├─ 跟踪遗留问题的持续改进
    └─ 更新合规检查知识库
```

## 失败模式规避

| 失败模式 | 描述 | 应对措施 |
|----------|------|----------|
| 检查流于形式 | 检查只是走流程，未发现实质问题 | 引入独立检查员；飞行检查；举报机制 |
| 问题整改不力 | 发现的违规问题未有效整改 | 明确整改责任；跟踪到底；升级机制 |
| 检查标准不一致 | 不同检查员标准不一，结果差异大 | 标准化检查清单；检查员培训；判定标准统一 |
| 整改反弹 | 整改完成后问题再次出现 | 建立长效监督机制；定期复核 |
| 经验未积累 | 同样的合规问题反复出现 | 根本原因分析；系统性改进；知识库积累 |
| 监管配合不当 | 监管检查时发现重大问题 | 前置合规检查；主动整改；建立预警机制 |
| 检查覆盖不全 | 重点领域未被检查到 | 风险导向的检查计划；覆盖度检查 |
